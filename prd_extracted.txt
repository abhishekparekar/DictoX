01. Product Overview
Build a premium, conversion-focused static website for DictoX Marketing, positioned as a Performance Marketing & Customer Acquisition Agency serving businesses across India.
The website should communicate a simple business outcome: advertising should not stop at clicks or leads; it should help businesses acquire customers, generate sales opportunities and grow consistently.
The experience should be original to DictoX Marketing. The supplied reference image and Adymize reference are design-direction inputs only; do not copy their branding, exact layouts, copy, illustrations or visual identity.

03. Product Goals & Success Criteria
1. Establish DictoX as a credible performance marketing and customer acquisition brand.
2. Explain the difference between generic advertising management and DictoX's business-growth approach.
3. Convert visitors into consultation enquiries through repeated, contextual CTAs.
4. Present genuine case studies, client logos and testimonials as trust proof without inventing data.
5. Make the website fast, responsive, accessible and SEO-friendly.
6. Make the structure scalable so case studies, testimonials, services and course content can be updated later.
04. Technology Stack
Frontend: React.js
Build Tool: Vite
Styling: Tailwind CSS
Icons: Lucide React or an equivalent lightweight icon library
Animation: CSS transitions + Framer Motion only where it materially improves UX; avoid animation overload.
Forms: React controlled form with validation. Connect to the final lead endpoint/API when supplied.
Map: Google Maps embed or supplied Google Maps embed URL.
Deployment: Vercel / Netlify / equivalent static hosting.
Data Model: Static JSON/JS objects for services, industries, case studies, testimonials and FAQs so content is easy to maintain.
No backend is required for V1 unless the client provides a lead-management/API requirement.
05. Visual Design Direction
Overall style: premium, modern, performance-driven, technology-led, editorial and conversion-focused.
Core visual idea: dark premium sections communicate performance, strategy and authority; light sections improve readability and create visual rhythm.
Use large typography, generous whitespace, rounded cards, thin borders, subtle glows, restrained gradients, data-focused visual blocks and clear CTA hierarchy.
The supplied screenshot indicates a dark/white alternating rhythm, emerald/green accents, metric cards, process steps, case-study cards and strong CTA bands. Reinterpret these patterns with an original DictoX system.
Do not use excessive glassmorphism, excessive neon, heavy 3D effects or distracting motion.

Dark glow recommendation: radial-gradient(circle at 50% 20%, rgba(24,230,160,.18), transparent 55%).
07. Typography System
Primary UI / Body Font: Inter. Use 400, 500, 600 and 700 weights.
Display / Heading Font: Space Grotesk. Use 500, 600 and 700 weights.
Hero heading: Space Grotesk, 64–76px desktop, 42–52px tablet, 36–42px mobile, tight line-height around 0.95–1.05.
Section heading: Space Grotesk, 42–56px desktop, 32–40px mobile.
Body: Inter, 16–18px desktop, 15–16px mobile, line-height 1.55–1.7.
Metric numbers: Space Grotesk, 30–48px, 600–700 weight.
Eyebrows/labels: Inter, 11–13px, 600 weight, uppercase with modest letter spacing.
Avoid more than two font families.
08. Layout & Responsive System
Desktop container: max-width 1200–1280px with 24px side padding.
Large desktop: max-width 1320px where the hero or case-study visuals need additional breathing room.
Tablet breakpoint: around 768px.
Desktop breakpoint: around 1024px.
Mobile: 360px–767px. All sections must remain readable and tappable.
Grid: 12-column desktop system; 2-column / 1-column responsive collapse as appropriate.
Section spacing: approximately 96–140px desktop, 64–90px tablet, 52–72px mobile.
Buttons: minimum 44px touch target height; pill/rounded style with clear hover and focus states.

Every primary CTA should lead to a consultation action. V1 can use a modal or dedicated /contact section.
Recommended fields: Name, Business Name, Phone/WhatsApp, Email, Business/Industry, Current Advertising Platform, Monthly Ad Budget Range, Primary Goal, Message.

Track CTA clicks and form submissions with the analytics platform selected by the client.

Page load: subtle fade/translate for hero content; avoid long splash screens.
Buttons: 150–250ms hover transition with small translateY(-1px) and controlled shadow/glow.
Cards: border/glow transition on hover.
Metric counters: optional count-up when the section enters the viewport, but display final values in HTML so content is accessible.
Process timeline: subtle reveal as each step enters viewport.
Case-study cards: image zoom 1.02–1.04 on hover.
FAQ: smooth accordion open/close.
Respect prefers-reduced-motion and disable non-essential animations when requested.

30. SEO Requirements
Page title: DictoX Marketing | Performance Marketing & Customer Acquisition Agency.
Meta description should naturally include performance marketing, Meta Ads, Google Ads, customer acquisition and India/Pune positioning.
Use one H1 only: Optimize Your Ads For More Profit.
Use semantic H2/H3 headings for all sections.
Add Organization / LocalBusiness structured data only with verified business information.
Add Open Graph and Twitter/X metadata.
Use descriptive alt text for founder, case-study and client visuals.
Use clean anchor IDs: #home, #services, #results, #industries, #about, #course, #contact.
31. Performance Requirements
Target Lighthouse: Performance 90+ where practical on production assets.
Optimize founder and case-study images using WebP/AVIF where supported.
Lazy-load below-the-fold images and videos.
Do not load heavy animation libraries unless required.
Use SVG icons and logos instead of large PNGs where appropriate.
Avoid layout shift by reserving image dimensions/aspect ratios.
Keep third-party scripts limited to required analytics, maps and approved integrations.
32. Accessibility Requirements
WCAG-oriented contrast for all text and interactive controls.
All buttons/links must have visible focus states.
Keyboard navigation for header, mobile menu, accordions and forms.
Semantic HTML: header, nav, main, section, article, footer.
Images require meaningful alt text; decorative images should use empty alt.
Form fields require labels and accessible error messaging.
Respect prefers-reduced-motion.
33. Content & Asset Rules
Production website must use only client-approved logo, founder photo, team images, client logos, case-study screenshots and testimonials.
Do not fabricate client names, logos, campaign numbers, testimonials, certifications or awards.
If an asset is pending, use a clearly marked development placeholder that cannot accidentally ship to production.
Client must supply: high-resolution logo, founder photos, genuine client logos, case-study data/screenshots, genuine testimonials/video testimonials, Google Maps embed link and service/business photographs.

FR-01 Header navigation scrolls to correct sections.

FR-04 Results cards support verified case-study content.

35. Acceptance Criteria
Visual: The final website feels premium, modern and original to DictoX, with dark/light section rhythm and emerald performance accents.
Content: All 16 planned content areas are represented and use the supplied approved copy.
Trust: Certification and client-proof areas use only approved assets and verified claims.
Conversion: Primary consultation CTA is visible in hero, relevant mid-page sections and final CTA.
Responsive: Mobile navigation, grids, cards, process and contact layout work without overflow.
Accessibility: Keyboard navigation, focus states, labels and semantic structure are implemented.
Performance: Images are optimized and below-fold assets are lazy-loaded.
SEO: One H1, logical headings, metadata, semantic anchors and alt text are present.
QA: Test Chrome, Edge, Firefox and Safari where available; test common mobile widths.
Production rule: no fake case-study data, fake logos, fake testimonials or unapproved claims.
36. Recommended Page Flow
Header → Hero → Trust/Certification → Business Problems → Services → Why DictoX → How We Work → Results/Case Studies → Industries → Client Logos → Testimonials → About/Founder → Meta Ads Course → FAQ → Final CTA → Contact/Map → Footer.
The flow intentionally alternates emotional/problem-led sections with proof, explanation and conversion moments. This prevents the page from becoming a long list of services.
37. Implementation Phases
Phase 1 — Setup: React/Vite/Tailwind, design tokens, fonts, global layout and routing/anchors.
Phase 2 — Core UI: Header, hero, trust, problems, services, why DictoX, process.
Phase 3 — Proof: results/case studies, industries, logos, testimonials, founder.
Phase 4 — Conversion: course, FAQ, final CTA, consultation form, contact/map, footer.
Phase 5 — Polish: responsive tuning, animations, accessibility, SEO, performance optimization.
Phase 6 — Client Content: replace all development placeholders with supplied approved assets and verified results.
Phase 7 — QA & Deployment: cross-browser test, Lighthouse review, production build and deployment.

39. Important Product Decisions
The website is a static React frontend in V1. It should not require a CMS unless the client later requests one.
Case studies and testimonials should be data-driven so new proof can be added without rebuilding UI components.
The website should prioritize business outcomes and proof over generic agency jargon.
Every claim that could be interpreted as a ranking, certification, client relationship or performance result must be verified before production.
The supplied screenshot is a visual reference for structure and visual rhythm, not a source for client facts.
